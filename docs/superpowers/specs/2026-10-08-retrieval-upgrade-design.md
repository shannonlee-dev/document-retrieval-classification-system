# Retrieval upgrade design

The supplied development brief is the authority. Build a teaching/demo CLI on the existing NumPy CSR system, preserve all 20 categories, loader, redaction, IDs, license, SVM and legacy command. Work on the current branch as explicitly requested; implementation is authorized without further design decisions.

- Extend `NumpyTfidfVectorizer(tf_mode="raw"|"log"|"double")`; reuse count rows and smooth IDF. Double TF uses the maximum of in-vocabulary counts in each row. Never densify the corpus.
- Keep `SearchResult`. `DocumentSearch.search(query, topk, strategy="scan"|"inverted")` retains positive-only results and ascending external ID ties. Inverted postings store internal rows and weights. Top-K uses a heap. Consistency tolerance: absolute score error 1e-12; ranking key rounds scores to 12 decimals to resolve floating-point ties.
- `NumpyBM25Retriever` uses direct positive Okapi IDF, k1=1.5, b=.75, full preprocessed token lengths, and unique query terms (no query-frequency multiplier). Share counts/postings structure. Empty/OOV user queries raise descriptive errors.
- Version 3 NPZ/JSON stores shared vocabulary, counts, row/column structure, snippets/IDs/labels once; three TF weight arrays, posting layout, BM25 IDF and lengths. Validate file digest, alignment and version before use. Legacy raw-only save/load API remains usable; full demo requires a full build.
- Build creates full-corpus indexes and retains existing classification/report outputs. Benchmark loads the same cached dataset, performs stratified 80/20 seed 42, fits on train only, and uses a recorded balanced held-out query subset (default 100 queries) for all quality methods. Zero-score results fill evaluation rankings deterministically, preserving existing metric definition; user search remains positive-only.
- E4 uses multiple short queries on 1k/5k/10k/all corpora, warm-up and repeated perf_counter measurements, reports build/load/latency and NumPy resident array bytes separately. E5 reuses the existing stopword ablation with a configurable paired seed/query budget, separate from historical ten-seed results.
- CLI: build / benchmark / demo / search / compare / interactive. Main wrapper and installed entrypoint share dispatch. Demo is offline, imports no training/plotting dependencies, and uses persisted benchmark evidence. Missing/incompatible artifacts and expected user errors return 2 without tracebacks. No color dependency.
- Reports include CSV, JSON, Markdown, environment/version/config/fingerprint/split/query IDs, per-class metrics, confusion matrices, safe error snippets, three Top-5 comparisons. No fabricated values; partial/unmeasured fields are explicit.
